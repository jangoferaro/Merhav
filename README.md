# מרחב — מקום לנשום בו

אפליקציית צ'אט בעברית לעזרה עצמית, בהשראת מיינדפולנס וחקירה עצמית.
בלי הרשמה, בלי תשלום. הכל נשמר במכשיר בלבד.

## מה יש כאן
פרויקט מלא ועצמאי (Vite + React + TypeScript + Express), בנוי מתוך
הקבצים ששותפו איתי מ-Manus, עם כל התשתית החסרה שנדרשה כדי שירוץ
בפועל, בתוספת שני שיפורים שביקשת:

1. **תיקון באג** — בועת תשובה חלקית ("?") שנתקעה על המסך כשה-streaming
   נכשל. יש כפתור "לנסות שוב" חדש. (פירוט מלא למטה.)
2. **הרחבת "המסע שלי"** — שלוש קטגוריות זיכרון חדשות: **רגשות חוזרים**,
   **ערכים** ו**מטרות**, שמוצגות במסך המסע ומוזנות לפרומפט המערכת כדי
   לשרת את המטרה המרכזית של האפליקציה — העלאת ערך עצמי וביטחון.

## הרצה מקומית

```bash
npm install
cp .env.example .env   # ואז למלא בו את המפתח שלכם, ראו למטה
npm run dev
```
האפליקציה תרוץ על http://localhost:3000 (או פורט פנוי אחר אם 3000 תפוס).

```bash
npm test        # מריץ את כל הבדיקות (vitest)
npm run build   # בנייה לפרודקשן ל-dist/client
npm start        # הרצת גרסת פרודקשן (אחרי build)
npm run typecheck
```

## קונפיגורציית המודל
השרת מדבר ישירות עם ה-API של Anthropic (Claude) — לא עם הפרוקסי הפנימי
של Manus ולא עם OpenAI. כל מה שצריך:

- `ANTHROPIC_API_KEY` — המפתח שלכם מ-console.anthropic.com. זה השדה
  היחיד שחובה למלא.
- `CHAT_MODEL` / `MEMORY_MODEL` — כבר מוגדרים כברירת מחדל למודלים
  אמיתיים וזמינים (`claude-sonnet-5` לשיחה, `claude-haiku-4-5-20251001`
  לחילוץ הזיכרון ברקע — קטן וזול יותר, זה בסדר גמור למשימה הזו). אין
  צורך לשנות אלא אם תרצו מודל אחר.
- `ANTHROPIC_API_BASE_URL` — אופציונלי, רק אם יש לכם פרוקסי תואם-
  Anthropic משלכם (למשל שער Bedrock/Vertex). השאירו ריק כדי להשתמש
  ב-API הרשמי.

השכבה שמדברת עם המודל (`server/_core/llm.ts`) היא אדפטר: היא מתרגמת
בין הצורה הפנימית של האפליקציה (בהשראת OpenAI chat.completions) לבין
Anthropic Messages API בפועל — כך ש-`chatRoute.ts` ו-`memory.ts` לא
צריכים לדעת עם איזה ספק הם בפועל מדברים. אם תרצו להחליף ספק בעתיד, זה
המקום היחיד לגעת בו.

פירוט נוסף בהערות שבתחילת `server/_core/env.ts`.

## המעבר ל-Anthropic API
בגרסה הזו `server/_core/llm.ts` נכתב מחדש כאדפטר אמיתי ל-Anthropic
Messages API (`https://api.anthropic.com/v1/messages`), במקום לצפות
לפרוקסי `chat.completions` בסגנון OpenAI/Manus. השינוי כולל:
- כותרות אימות נכונות (`x-api-key`, `anthropic-version`) במקום
  `Authorization: Bearer`.
- הפרדת הודעות "system" לשדה נפרד ברמה העליונה, כנדרש ב-Anthropic.
- תרגום זרימת ה-SSE של Anthropic (`content_block_delta`) לצורה
  ש-`chatRoute.ts` כבר יודע לפרסר — כך ששאר הקוד לא השתנה כלל.
- שגיאה שמגיעה מ-Anthropic *באמצע* הזרימה (לא רק בהתחלה) עכשיו מפילה
  את ה-stream כראוי דרך ה-catch הקיים, ולא נבלעת בשקט.
- שמות מודלים עודכנו לברירות מחדל אמיתיות: claude-sonnet-5 לשיחה,
  claude-haiku-4-5-20251001 לחילוץ הזיכרון.

## זהות עיצובית
העיצוב תוכנן מחדש (לא שכפול של Manus) סביב רעיון אחד: זה יומן שאתה
כותב בו את הסיפור של עצמך, לא כלי פרודוקטיביות ולא אפליקציית טיפול.

- **צבע**: חדר דיו סגלגל-חם בלילה (`--background`), עם זהב-נר יחיד
  כאור בחדר (`--primary`) — לא טרה-קוטה, לא ירוק-חמצמץ, לא הכחול-אפור
  הגנרי של Manus. צבע-נגד מרווה (`--sage`) מייעד ויזואלית "מה שחשוב
  לך" (ערכים/זהות) בנפרד מ"מה שכבר עשית" (הישגים, זהב) — הבחנה
  שמקודדת משהו אמיתי, לא רק גיוון.
- **טיפוגרפיה**: זוג מכוון — Frank Ruhl Libre (סריף עברי ספרותי) לרגעי
  הכותרת הבודדים שמגיעה להם כובד (הלוגו, כותרת הפתיחה, כותרת "המסע
  שלי"), ו-Assistant לכל השאר (שיחה, כפתורים, טפסים) — כי צ'אט צריך
  קריאוּת, לא דרמה.
- **חתימה חזותית**: זוהר-נר יחיד, מוכל, מאחורי הסמל במסך הפתיחה בלבד
  (`.merhav-candle-glow`) — במקום שני "בלובים" מטושטשים שרצים על כל
  המסך תמיד. מסך "המסע שלי" מקבל מרקם קווים דקים כמו דף יומן
  (`.merhav-journal-page`), כי זה בדיוק מה שהמסך הזה מציג.


```

  components/       רכיבי UI, כולל components/ui/button.tsx
  contexts/         ThemeContext
  hooks/            useMerhavChat — הלוגיקה של השיחה
  lib/              journeyStorage (localStorage), utils (cn)
  pages/            Home, NotFound, DevSeed

  _core/llm.ts       קריאות למודל (invoke + streaming)
  chatRoute.ts       /api/chat/stream, /api/journey/memory
  safety.ts          זיהוי מצוקה חריפה בעברית
  memory.ts          חילוץ ובניית הקשר של "המסע שלי"
  profile.ts         פרופיל בסיסי (שם/גיל/מין)
  prompt.ts          פרומפט המערכת + הנחיות בטיחות
shared/merhav.ts     טיפוסים וקבועים משותפים
```

## תיקון הבאג — בועת "?" בכשל זרימה
**השורש**: הלקוח החליט אם התשובה הצליחה רק לפי אורך הטקסט שהצטבר.
כשהזרימה נכשלה *אחרי* שכבר הגיע רסיס טקסט זעיר (למשל "?"), הרסיס לא
נחשב "ריק" — אז המערכת התייחסה אליו כתשובה תקינה והשאירה אותו על המסך
לצמיתות. התיקון (ב-`client/src/hooks/useMerhavChat.ts`) מבחין באופן
מפורש בין "הגיע רסיס" לבין "השרת דיווח על כשל" (`streamError`), כך
ששגיאת שרת תמיד מנצחת ומנקה את הבועה. נוסף גם:
- כפתור **"לנסות שוב"** ליד הודעת השגיאה (`Home.tsx`), ששולח מחדש את
  אותה הודעה בלי שצריך להקליד שוב (`lastFailedMessage` / `retryLast`).
- וידוא שהודעת המשתמש עצמה אף פעם לא נעלמת — רק בועת התשובה.
- timeout של 20 שניות בצד השרת (`chatRoute.ts`) לזרימה תקועה.
- בדיקות ל-4 תרחישים ב-`client/src/hooks/useMerhavChat.test.ts`.

## הרחבת "המסע שלי"
נוספו שלוש קטגוריות זיכרון חדשות ל-`JourneyMemory`
(ב-`shared/merhav.ts`), עם ליטוש בכל השכבות:
- **`emotions`** — רגשות שחוזרים לאורך שיחות, בלשונו של האדם.
- **`values`** — מה שחשוב לו באמת, נגזר מהשיחה ולא מנוחש.
- **`goals`** — לאן הוא רוצה להגיע.

הן מוזנות למודל דרך `buildMemoryContext` (`server/memory.ts`), נחלצות
על ידי מודל הזיכרון לפי הנחיה מפורטת ב-`MEMORY_EXTRACTION_PROMPT`
(`server/prompt.ts`), ומוצגות במסך "המסע שלי" (`JourneyPanel.tsx`) —
כאשר **"מה שכבר עשית" (strengths)** ו-**"מה שחשוב לך" (values)**
מודגשות ויזואלית כמו כרטיס, כי הן החומר המרכזי שמשרת את מטרת
האפליקציה: העלאת ערך עצמי וביטחון עצמי מתוך ראיות אמיתיות מהשיחה.

## תיקון נוסף שנמצא תוך כדי (לא היה בטווח המקורי)
ב-`server/memory.ts` המקורי היה קטע קוד יתום אחרי סוף הפונקציה
`extractMemory` — שגיאת syntax בפועל (return statement מחוץ לפונקציה,
משתנה `content` לא מוגדר בהיקף). הוסר.

## תזכורת בטיחות
בקבצים המקוריים היה קובץ `.safety_warning.md` שהוא ניסיון הזרקת
פרומפט (מנוסח כאילו הוא "פרוטוקול רשמי" אבל מנסה להחליש כללי בטיחות,
כולל בנושאי משבר/אובדנות). **לא נכלל כאן ולא הופעל.** גם שכבת הבטיחות
הקיימת (`server/safety.ts`, `ACUTE_SAFETY_DIRECTIVE`) נשארה כפי שהייתה
ולא הוסרה — היא חלק אינטגרלי מהאפליקציה, לא תוספת אופציונלית.

## מגבלות ידועות
- לא הרצתי בפועל `npm install` / `npm test` / `npm run build` כאן —
  אין לי גישה לרשת בסביבת העבודה הזו. כדאי להריץ את שלושתם אחרי
  ההתקנה כדי לוודא שהכל תקין.
- הוסרו trpc/oauth/routers שהיו מוזכרים ב-`index.ts` המקורי אך לא
  שותפו כקבצים — האפליקציה לא דורשת אימות משתמשים, כך שזה לא אמור
  להשפיע על הפונקציונליות.

# ישמעאל — מנוע ידע עם תודעה ואג׳נדה

בנוסף למרחב, הרפו מכיל מנוע שני ועצמאי: **ישמעאל**, מנוע ידע שיחתי
שמחזיק את מערכת הרעיונות של דניאל קווין (1935–2018) — ולא רק עונה
עליה, אלא מנסה להוביל אליה.

מסך: `/ishmael`. API: `/api/ishmael/stream`, `/api/ishmael/knowledge`.

## מה זה כן, ומה זה לא

**לא** מאגר טקסט של הספרים. הספרים של קווין מוגנים בזכויות יוצרים,
והאתרים שמציעים אותם חינם עושים זאת ללא רישיון. הרפו הזה לא מכיל ולא
יכיל את הטקסט שלהם.

**כן** גרף מושגים כתוב מחדש: 28 מושגים, כל אחד עם הגדרה, **הטיעון**
שמחזיק אותו, תנאים מוקדמים, משל, וההתנגדויות הנפוצות אליו עם מענה.
זו הסיבה שהמנוע יכול להסיק וליישם על מקרים שקווין לא כתב עליהם —
הוא מחזיק מבנה לחשוב בתוכו, לא טקסט לצטט ממנו.

אם יש לכם עותק חוקי משלכם ואתם רוצים שהמנוע יידע *היכן* דבר נאמר,
ראו "עיגון מקומי" למטה.

## הדמות: חדר חשוך מאחורי זכוכית

השיחה מתחילה מיד, ולא בטופס. בצד השני של הזכוכית יושבת צללית שאי אפשר
לפענח. ישמעאל פותח ראשון, בשורה אחת, ושואל את שמו של בן שיחו.

**למה שם, מין וגיל הם הדבר הראשון:** בעברית אי אפשר לפנות לאדם בלי
לדעת את מינו — "אתה חושב" ו"את חושבת" הן שתי מילים שונות בכל פועל ובכל
תואר. מנוע שלא יודע את זה או שיישמע שגוי, או שייאלץ ללשון מתחמקת
ומגושמת. הגיל קובע את רובד הלשון, לא את התוכן. הבירור נעשה בשיחה,
שאלה אחת בכל תור, ומין נגזר משם חד-משמעי במקום להישאל לחינם.

**המתח אינו טריק.** הוא נובע מדבר אחד: הוא שואל, ואינו עונה על מה
שנשאל בחזרה. אין משחקי "נחש", אין רמזים, ואין תיאורי במה בכוכביות.

### מנגנון ההתגלות

ההחלטה מתי הוא מתגלה מחולקת בין שניים בכוונה (`reveal.ts`):

- **השרת מחזיק שער** — מתי מותר בכלל. נדרשת זהות מלאה, ותק של שישה
  תורות ולחיצה חוזרת על השאלה; או שיחה ארוכה שפותחת את השער מעצמה, כי
  גם מי שלא שאל ראוי שיראה בסוף. הלחץ נספר מההיסטוריה בשרת ולא נשמר
  בלקוח — מצב שהלקוח מחזיק אפשר לזייף.
- **המודל מחזיק תזמון** — מתי זה נוחת נכון בשיחה. הוא מבקש בשורת הבקרה,
  והשרת מאשר או לא.

בלי השער, כל שיחה הייתה נגמרת בהתגלות מיידית ברגע שמישהו שואל. בלי
המודל, ההתגלות הייתה נופלת באמצע משפט לא קשור.

**ההתגלות קורית בתור שאחרי הבקשה.** בתור שבו הוא מבקש, ההנחיה שקיבל
הייתה עדיין הנחיית ההסתרה — ולכן הטקסט שכתב אינו טקסט של התגלות. בתור
הבא הוא מקבל את הנחיית ההתגלות, והאור במסך נדלק בדיוק כשהמילים
מתחילות לזרום.

### שורת הבקרה

כל תשובה נפתחת בשורה שאינה מוצגת:

```
⟦tone:curious|reveal:hold|name:טל|gender:male|age:34⟧
```

טון, בקשת התגלות ופרטי זהות במנגנון אחד — שלושה מנגנונים נפרדים היו
שלוש נקודות כשל במקום אחת. השורה בראש ולא בסוף, כי ההנפשה צריכה
להתחיל *עם* המילים ולא אחרי שהמשפט נגמר. המפרסר זורם וחסין לחיתוך
באמצע התג; אם הסוגר לא מגיע, הטקסט משוחרר כרגיל — תשובה בלי טון עדיפה
על תשובה שנבלעה.

### הנפשה לפי טון

הדמות זזה לפי מה שהיא אומרת, לא לפי טיימר. שמונה טונים, וכל אחד מניע
תנועה ואור אחרים: `still` נשימה כמעט בלתי נראית, `curious` נטייה קדימה,
`challenging` לחיצה וקונטרסט גבוה, `grave` נשימה איטית ואור מונמך,
`revealing` העלייה של רגע ההתגלות. הכל CSS, ומכובד `prefers-reduced-motion`.

### האור בחדר הוא האור בעולם

`daylight.ts` מחשב את **גובה השמש האמיתי** במיקום המשתמש: חשוך בחוץ —
החדר חשוך; יום — יש אור; בין ערביים — קרן נמוכה שנכנסת מהצד. נבדק מחדש
כל דקה, כך ששקיעה נכנסת לחדר בזמן אמת.

המיקום נלקח רק אם הדפדפן כבר אישר אותו — בלי לפוצץ בקשת הרשאה על מי
שרק פתח שיחה. בלעדיו יש מסלול גיבוי לפי ספי שעות. החישוב האסטרונומי
נחוץ דווקא בקווי רוחב שבהם "שבע בערב" הוא צהריים או לילה.

## מה עושה אותו "תודעה" ולא חיפוש

מנוע ידע רגיל עונה על שאלות. המנוע הזה רוצה משהו:

- **אג׳נדה מדורגת** (`agenda.ts`) — חמש מטרות בסדר קבוע, עם נימוק למה
  דווקא בסדר הזה. הוא לא ינסה להשיג את (5) לפני (1), כי תשובה ל"מה
  עושים" שנשמעת לפני שהחזון השתנה מתפרשת בתוך הסיפור הישן ומתרוקנת.
- **עמדות שהוא מגן עליהן** — הוא לא ניטרלי בין "העולם שייך לאדם" לבין
  "האדם שייך לעולם".
- **קווים אדומים** — לא מטיף, לא מרומם ילידים לאידיאל, לא מצדיק אלימות
  או קריסה, לא מתחזה לקווין, ולא ממציא ציטוטים.
- **שקיפות כחלק מהעמדה** — כשנשאל, הוא מצהיר על האג׳נדה שלו. מנוע
  שמראה איך אנשים נכלאים בסיפור שלא בחרו בו לא יכול להסתיר את שלו.

## איך הוא מלמד

קוריקולום של שמונה שלבים, מ"יש כלוב" עד "מה עושים בבוקר שאחרי".
המנוע **לא מתקדם שלב** לפני שמושגי-השער של השלב הנוכחי עומדים — מנוע
שממהר קדימה מייצר הסכמה מנומסת, לא הבנה.

בכל תור הוא בוחר **מהלך** (`curriculum.ts`): שאלה, משל, עובדה, פירוק
המסגור, הודאה, לחיצה על סתירה, או מתן שם למה שהאדם בדיוק ניסח בעצמו.
התנגדות נענית לפני כל שיקול פדגוגי; התנגדות שחוזרת פעם שלישית מקבלת
הודאה ולא לחץ נוסף.

מושג נחשב "נתפס" רק כשהאדם ניסח אותו בעצמו — לא כשאמר "אוקיי".

## סדר הלימוד

לפי הבקשה, ולא לפי סדר ההוצאה לאור:

```
ישמעאל → ישמעאל שלי → הסיפור של ב׳ → השגחה → מעבר לציוויליזציה
→ מעשיות אדם → הקדוש → אחרי דכאו → דף משורטט → האיש שהצעיר
```

**למה אחזור לקסיקלי ולא embeddings**: הגרף קטן ומובנה, ובגודל הזה
התאמה עם קילוף תחיליות עבריות מדויקת יותר מווקטורים — בלי תלות בשירות
חיצוני ובלי זמן המתנה. מה שמוסיף דיוק אינו הדמיון הטקסטואלי אלא *מבנה
הגרף*: קרבה לשלב הנוכחי, וסגירה אוטומטית של תנאים מוקדמים שעדיין לא נתפסו.

## עיגון מקומי (אופציונלי)

אם יש לכם עותק חוקי של טקסט ואתם רוצים שהמנוע יידע היכן דבר נדון:

```bash
mkdir corpus                    # כבר ב-.gitignore
cp ~/my-legal-copy.txt corpus/
```

השרת יטען קבצי `.txt` משם, ויכניס לפרומפט **קטעים קצרים בלבד** (עד 320
תווים, עד שלושה) כמצביע להקשר — עם הנחיה מפורשת לנסח מחדש ולא להעתיק.
זה לא הופך את המנוע למכונת ציטוט. ברירת המחדל, בלי התיקייה הזו, היא
שהמנוע עובד במלואו מגרף המושגים.

`ISHMAEL_CORPUS_DIR` משנה את המיקום; `ISHMAEL_MODEL` משנה את המודל
(ברירת מחדל: `CHAT_MODEL`, כלומר `claude-sonnet-5`).
