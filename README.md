# SAFE WALK — Phase-0 prototype

ניווט עירוני להולכי רגל שממליץ על הדרך העדיפה לפי הקשר בטיחותי בזמן אמת —
ומסביר בפשטות למה.

זהו **שלב 0 (Prototype)** מתוך ה-Roadmap שבאפיון: `UI + routing + SAFE reasons`,
לבדיקת desirability וחוויית ההסבר. הוא רץ מקצה לקצה, בלי מפתחות API ובלי
חיבור לאינטרנט, ומייצר המלצה אמיתית ממנוע דטרמיניסטי — לא הדמיה של מסך.

```bash
npm install
npm run dev      # http://localhost:3000
npm test         # 141 בדיקות
npm run build
```

## העיקרון שהקוד בנוי סביבו

> **ה-AI מסביר — לא מחליט.**

באפיון זה עיקרון מוצרי ובטיחותי מרכזי (פרקים ג׳ ו-י׳). כאן הוא **מבני**, לא
הנחיה בפרומפט:

| שלב | מי מחליט | הקובץ |
|---|---|---|
| חלופות גיאוגרפיות | מנוע רוטינג, בלי שום signal בטיחותי | `server/routing/` |
| ציון מקטע | חישוב משוקלל על signals עם מקור, גיל ו-TTL | `server/safety/segmentScore.ts` |
| ציון מסלול | `0.65 × ממוצע + 0.35 × המקטע החלש` | `server/safety/routeScore.ts` |
| **בחירת המסלול** | **utility + שער עיקוף — קוד בלבד** | `server/safety/decisionPolicy.ts` |
| סיבות | אוצר מילים סגור של `ReasonCode` | `server/safety/reasons.ts` |
| ניסוח | תבנית דטרמיניסטית, ואופציונלית LLM | `server/explain/` |

עד שמגיעים לשכבת השפה, ההחלטה כבר סופית. מודל השפה מקבל אך ורק את
`ExplanationPayload` — אובייקט סגור עם קודי סיבה מאושרים. אין ממנו מסלול
לאחסון ה-signals, לדיווחים, לגיאומטריה או לזהות משתמש. אם המפתח חסר, אם
הקריאה נכשלת או אם הטיוטה נפסלת — התבנית הדטרמיניסטית עונה, וההמלצה לא
משתנה.

בדיקות שמחזיקות את זה: `tests/acceptance.test.ts` (FR-05) ו-`tests/explain.test.ts`.

## מה עובד בפועל

- **מפה, A/B, חיפוש יעד** — מסכים S01–S08 מפרק ו׳.
- **שניים עד שלושה מסלולי הליכה** מגרף רחובות אמיתי של תל אביב.
- **SAFE Score** לכל מקטע לפי שבעת ה-signals מפרק ח׳, במשקלים נפרדים ליום וללילה.
- **Confidence נפרד לגמרי** מהציון, לפי מקור, טריות, רזולוציה, corroboration וכיסוי (פרק י״ג).
- **מדיניות עיקוף** לפי טבלת פרק ז׳ — 0–3 / 4–7 / 8–12 / מעל 12 דקות.
- **הסבר** בעברית, 2–4 שורות, עם guardrails נאכפים בזמן ריצה.
- **ניווט חי** — מיקום, זיהוי סטייה, re-evaluate עם היסטרזיס, באנר S05 רגוע.
- **דיווחי קהילה** עם TTL לפי קטגוריה, corroboration ומשקל trust שלא נחשף.
- **העדפות** שמזיזות באמת את ההמלצה, לא מתגים דקורטיביים.
- **פרטיות** — נשמר רק המיקום האחרון, והוא נמחק ברגע שה-session נגמר.

### קריטריוני קבלה

## מה **לא** מיושם, ולמה

הפרוטוטייפ לא מעמיד פנים שהוא ה-MVP. הפערים הם החלטות, לא חובות שנשכחו:

**נתונים.** אין חיבור חי ל-Open Data של תל אביב, ל-GTFS/SIRI, ל-data.gov.il או
לספק POI. `server/safety/signalStore.ts` מייצר signals מפרופילים מכוילים ידנית
לפי שעה — עם אותו מבנה בדיוק שמקור אמיתי יחזיר (`source`, `observedAt`,
`expiresAt`, `confidence`, `corroboration`), כך שכל feed נכנס במקומו בלי לגעת
במנוע. פרק כ״ה מציין במפורש שצריך לבדוק רישוי ותנאי שימוש לכל מקור לפני
production — וזה לא נעשה.

**רוטינג.** אין Mapbox ואין GraphHopper. יש גרף רחובות כתוב ביד של האזור
פלורנטין–אלנבי. פרק כ״א משאיר את שאלת הספק פתוחה, ולכן `RoutingProvider`
הוא ממשק עם מימוש אחד: החלטה שנשארת הפיכה. הקואורדינטות מקורבות אך עקביות —
כל מרחק וכל ETA מחושבים מהן, לא מקודדים.

**התמדה.** הכול בזיכרון. אין PostGIS, אין Redis, אין מודל משתמשים. אין
Share Walk, אין check-in, אין Admin/Control Center, אין תמונות בדיווח
(פרק כ״א מגדיר את זה כשאלה פתוחה, ולא רציתי לפתוח משטח מודרציה ופרטיות
לפני שהיא נסגרת).

**המשקלים אינם ממצא בטיחותי.** כל מספר ב-`server/safety/weights.ts` הוא
השערה, כפי שהאפיון דורש לומר. לפני שימוש אמיתי נדרשים מחקר משתמשים,
כיול, ובדיקת bias.

## שאלות פתוחות שהפרוטוטייפ עונה עליהן

פרק כ״א מונה שאלות לסגירה לפני build. שתיים מהן קיבלו כאן תשובה ראשונה,
כקוד שאפשר לבדוק ולהחליף:

**"איזה signals מקבלים משקל ביום לעומת לילה?"** → `DAY_WEIGHTS` ו-`NIGHT_WEIGHTS`.
בלילה תאורה ונוכחות אנושית עולות, ההקשר ההיסטורי יורד. שני הפרופילים חייבים
להסתכם ב-1 בדיוק, ויש על כך בדיקה — אחרת `coverage` מפסיק להיות "אחוז תקציב
המשקל שיש עליו נתונים", וה-confidence נשבר בשקט.

**"מהו detour default?"** → `auto`, כלומר טבלת פרק ז׳ עצמה. המשתמש יכול
להחמיר ל-3/5/10 דקות, אבל לא להרפות מעבר לתקרה של 12.

השאר נשארו פתוחות: ספק המפות, מקור ה-POI, זמן שמירת session, תמונה בדיווח,
ומנגנון בדיקת ה-bias.

## החלטות שכדאי לדעת עליהן

**"אין מידע" לעולם לא הופך ל"מסוכן".** signal חסר פשוט לא נפלט מה-store,
והמשקלים מנורמלים מחדש על מה שקיים. החוסר משפיע על `coverage` ומשם על
`confidence` — לא על הציון. זהו החוק שהכי קל להפר בטעות, ויש עליו בדיקה
ייעודית.

**הציון לא מסתיר מקטע חלש.** `0.65 × ממוצע משוקלל באורך + 0.35 × המקטע החלש
המשמעותי` — כדי שמסלול עם 95% מקטעים טובים ומקטע בעייתי אחד לא יראה תקין.
"משמעותי" מוגדר כרף אורך, אחרת מחבר של שישה מטרים היה שולט בציון.

**שעון העיר, לא שעון השרת.** "זמן הוא חלק מהכתובת" — לכן `cityTime.ts` קורא
את השעה ב-`Asia/Jerusalem` תמיד. שימוש ב-`Date#getHours` היה הופך את ה-SAFE
Score לתלוי ב-TZ של הדפלוימנט.

**שער העיקוף אינו כפילות של פונקציית ה-utility.** ה-utility סוחרת בטיחות
מול זמן ברציפות, ובלי שער הייתה מוכרת ברצון עיקוף של 14 דקות תמורת שיפור
גדול. הטבלה של פרק ז׳ היא זו שעוצרת את זה. `assertNegligibleRuleIsEnforced()`
נקראת בטעינת המודול ומוודאת ששני הספים לא נסחפים זה מזה.

**ה-guardrails נכתבו בלי `\b`.** ב-JavaScript `\b` מוגדר מול ASCII, ואותיות
עבריות אינן `\w` — כך ש-`/\bבטוח\b/` לעולם לא מתאים. הגרסה הראשונה כאן נכתבה
כך, והבדיקה תפסה את זה: כל החצי העברי של שכבת ההגנה היה עובר הכול בשקט.
`shared/guardrails.ts` בונה גבול-מילה עם lookarounds של Unicode, ומתיר גם
אות תחילית אחת ("ובטוח", "הבטוח").

**אין אדום בשום מקום.** פרק ב׳ שולל "מפת פחד", ופרק י״א מבקש הודעות רגועות.
המסלול המומלץ מסומן בחום, לא באזהרה; "להישאר במסלול" אף פעם לא הכפתור הקטן.

## מבנה

```
shared/          חוזה משותף — טיפוסים, אוצר מילות הסיבות, guardrails
server/
  routing/       גרף, חיפוש חלופות, ממשק ספק
  safety/        signal store, ניקוד מקטע ומסלול, confidence, מדיניות החלטה
  explain/       payload, תבנית, ולידציה, אדפטר Anthropic
  api/           /v1/routes/evaluate, /v1/walks, /v1/reports, /v1/health
  state/         walk sessions (בזיכרון, מיקום אחרון בלבד)
client/src/
  pages/         S01 Home, S02+S03 Recommendation, S04+S05 Walking,
                 S06 Arrived, S07 Report, S08 Preferences
tests/           141 בדיקות, כולל FR-01..FR-10 ותרחיש פלורנטין
```

## API

| Endpoint | תפקיד |
|---|---|
| `POST /v1/routes/evaluate` | A/B + העדפות → מסלולים, המלצה, סיבות, הסבר |
| `GET /v1/segments/:id/explain` | פירוט signals, מקורות וגילאים למקטע |
| `POST /v1/walks` | פתיחת session |
| `PATCH /v1/walks/:id/location` | עדכון מיקום, זיהוי סטייה |
| `POST /v1/walks/:id/reevaluate` | האם להציע מסלול אחר |
| `POST /v1/walks/:id/arrive` | סיום — המיקום נמחק מיד |
| `POST /v1/reports` · `/confirm` | דיווח קהילתי, אישור/סתירה |
| `GET /v1/health/data-feeds` | מצב המנוע וקונפיגורציית המודל |

## הרצה עם LLM (אופציונלי)

```bash
cp .env.example .env   # ואז ANTHROPIC_API_KEY=...
```

זה משנה רק את **הניסוח**. ההמלצה, הציונים והסיבות זהות לחלוטין, ואם המודל
חורג מהאוצר מילים או ממציא מספר — הטיוטה נזרקת והתבנית עונה במקומה.
`GET /v1/health/data-feeds` מונה כמה טיוטות נפסלו.
