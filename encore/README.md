# Jocares.: מנוע להגדלת קהל

**Be Jo.** · Because art deserves an audience.

אמנים מפרסמים הופעה. כל אחד יכול לשתף אותה ולהרוויח כסף מכל כרטיס שנמכר בזכותו. (שם קוד בריפו: `encore`. המותג: Jocares., ראו [DESIGN.md](DESIGN.md) ו-[brand/](brand/).)
ובנוסף, **מודול תוכן**: אמנים מזמינים תוכן וחשיפה מיוצרים מהציבור, במחיר ידוע מראש, גם כשאין הופעה קרובה.
זה MVP לפיילוט סגור, לפי ה-PRD בגרסה 1.0. ההחלטות שבהן פישטתי את ה-PRD או סטיתי ממנו מתועדות ב-[DECISIONS.md](DECISIONS.md).

## הרצה

צריך Node 22.13 ומעלה. **אין תלויות ואין `npm install`.** המערכת משתמשת רק ב-HTTP, SQLite ו-crypto המובנים ב-Node.

```bash
cd encore
npm run seed     # נתוני הדגמה: הופעות (עם תמונות הדגמה), מקדמים, מכירות, יוצרים
npm start        # http://localhost:3000
npm test         # 48 בדיקות: כרטיסים, תוכן, מסעות מלאים דרך HTTP, אבטחה
```

הכניסה היא עם קוד חד-פעמי למייל. במצב פיתוח הקוד מוצג על המסך.

## איך זה עובד

**אמן:** מדביק לינק להופעה (המערכת קוראת JSON-LD ו-Open Graph), בוחר סכום קבוע לכרטיס,
רואה חלוקה של מקדם / ENCORE / אמן, ומפרסם. אחר כך יש לו מסך תוצאות, מקדמים מובילים,
השהיה, סיום, ביטול, שינוי תגמול למכירות עתידיות ומגבלת כרטיסים.

**מקדם:** גולש בלי הרשמה. ההרשמה נדרשת רק כשלוחצים "שיתוף והרווחה". מקבל לינק אישי והודעה מוכנה עם גילוי נאות,
ויש לו כפתורי שיתוף: WhatsApp, Telegram, Facebook, הודעה, Instagram (העתקה) ושיתוף מובנה של המכשיר.
אחר כך יש לו מסך מכירות, ומסך כסף עם שלושה מצבים: ממתין, זמין, שולם. משם מבקשים העברה.

**רוכש:** לוחץ על לינק ורואה גילוי נאות ("X המליץ/ה, ומקבל/ת עמלה"). עובר לקופה של ספק הכרטוס, והשיוך עובר דרך `ref`, בלי קוד ידני.
אחרי הקנייה אפשר להירשם לעדכונים מהאמן (בהסכמה מפורשת) או להפוך למקדם בעצמו.

**מודול תוכן:**
- **אמן:** נכנס דרך "מה תרצה שיקרה?" (`/grow`), מגיע לרשימת יוצרים מותאמת, ומזמין שירות במחיר ידוע.
  את הבריף המערכת בונה אוטומטית, וזכויות השימוש נבחרות מתוך שלושה מסלולים מוכנים.
  הכסף נתפס כהרשאה אצל ספק התשלומים ונגבה רק כשהעבודה מאושרת.
- **יוצר:** פרופיל בסיסי (`/creator`), שירות מתבנית עם מחיר, הזמנות. דף ההזמנה (`/orders/:id`) משותף לשני הצדדים,
  והפעולה הבאה מופיעה בראש הדף: אישור, העלאת תוצר, תיקון, פרסום ואימות.
- **היברידי:** הזמנה שקשורה להופעה פעילה נותנת ליוצר לינק אישי, והוא מקבל גם עמלה על כל כרטיס.
- **הגנות זמן:** יוצר שלא הגיב תוך 3 ימים, ההזמנה מתבטלת והאמן לא מחויב.
  אמן שלא הגיב לתוצר תוך 5 ימים, התוצר מאושר אוטומטית.
  פרסום שלא אומת תוך 3 ימים נחשב מאומת לפי הקישור, ומסומן ככזה.

**תפעול (`/admin`):**
- בדיקת התאמה כספית
- אישור העברות
- טיפול בפניות, עם התאמה כספית מתועדת
- הקפאת תגמול או משתמש
- יומן פעולות
- כלי הספק המדומה: החזר, ביטול הופעה, ושליחה כפולה של webhook

## ארכיטקטורה

מונולית מודולרי (PRD §21: "אין דרישה ל-Microservices"):

```
src/
  domain/identity.js   Identity & Access: קוד למייל, סשנים, הרשאות, Audit, התראות
  domain/campaigns.js  Artist & Event + Campaign Engine (מצבים, תנאים בגרסאות) + Marketplace (דירוג מבוסס חוקים)
  domain/referrals.js  לינקים אישיים, לחיצות, טקסט שיתוף
  domain/ingest.js     Attribution Engine + Commission Engine. נקודת הכניסה היחידה של כסף
  domain/money.js      Ledger & Payouts: יתרות, שחרור אחרי ההופעה, תשלומים, מחלוקות, בדיקת התאמה
  domain/extract.js    Content: חילוץ פרטי הופעה מלינק (עם הגנת SSRF)
  domain/content.js    מודול התוכן: פרופילים, שירותים, התאמה, הזמנות, תוצרים, זכויות, אימות פרסום, מחלוקות
  providers/           ספק כרטוס Sandbox (sim.js) וספק תשלומים Sandbox להזמנות תוכן (simpay.js)
  views/               HTML בצד השרת, RTL, escape אוטומטי
  http.js server.js    ניתוב, CSRF, rate limit, כותרות אבטחה
```

### זרימת הכסף
1. **לחיצה** (`/r/:code`): נרשמת לחיצה עם מזהה הפניה ייחודי ונשמרת עוגייה ל-30 יום. לחיצה מאוחרת יותר מחליפה אותה.
2. **רכישה:** הרוכש עובר לספק עם `ref`. **רק webhook חתום מהספק** יוצר הזמנה. לחיצות לבדן לא שוות כסף.
3. **שיוך** (`decideAttribution`): נבדקים חלון הזמן, התאמה לקמפיין, שהקמפיין פעיל, שהמקדם לא מוקפא, שזו לא רכישה עצמית, ומכסת הקידום.
   כל החלטה נשמרת עם סיבה קריאה, כדי שאפשר יהיה לטפל במחלוקות.
4. **תגמול:** נוצר במצב `pending`, לפי גרסת התנאים שהייתה בתוקף ברגע העסקה, וכל שינוי נרשם ב-`ledger`.
5. **שחרור:** 3 ימים אחרי ההופעה התגמול עובר ל-`payable`.
6. **תשלום:** המקדם מבקש, צוות התפעול מעביר (ידנית בפיילוט) ומסמן עם אסמכתא, והתגמול עובר ל-`paid`.
7. **החזר או ביטול:** אם התגמול עוד לא שולם, הסכום יורד. אם כבר שולם, נוצר קיזוז (`clawback`) מהתשלום הבא.

### הבטחות שנבדקות בבדיקות
- webhook כפול, או אותה הזמנה באירוע אחר, לא יוצרים תגמול כפול
- החזר שמגיע לפני הרכישה נדחה עם 409, כדי שהספק ינסה שוב, ולא נרשם כמעובד
- `sum(ledger) == amount` לכל תגמול, וסכום כל העברה שווה לתגמולים שבה
- היומן הכספי ויומן הפעולות לא ניתנים לעריכה או מחיקה (triggers ב-SQLite)
- סכומים נשמרים במספרים שלמים באגורות. אין חישובי כסף ב-floating point
- CSRF, מניעת open redirect, XSS, חתימת webhook, הרשאות לפי בעלות

## מה חסר לפני השקה מסחרית
1. **ספק כרטוס אמיתי.** מוסיפים מתאם ב-`src/providers/` (ראו `index.js`). הליבה לא משתנה.
   זה הדבר הראשון לבדוק: אילו ספקים בישראל מעבירים מזהה הפניה ושולחים webhooks.
2. **ייעוץ משפטי וחשבונאי:** מס על תשלומים לאנשים פרטיים, חשבוניות, תנאי שימוש מחייבים. הטקסט ב-`/terms` הוא טיוטה.
3. **ספק תשלומים להעברות.** בפיילוט ההעברה ידנית ומתועדת.
4. Postgres במקום SQLite, ו-Redis ל-rate limit, אם רצים על יותר משרת אחד.
5. גיבויים, ניטור ושליחת התראות במייל או ב-push (היום ההתראות רק בתוך המערכת).
